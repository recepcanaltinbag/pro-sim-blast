4 · How a genus is decided

The statistical rule of this database is that a signal is tested at entry, sequence and genus level, and that the genus level decides. That makes the genus the unit of every published signal — so it has to be a classification, not a string operation.

Until 2026-11-11 it was a string operation. The genus was taken as the first word of the GenBank organism name, independently in sixteen places across the pipeline and the web application. Two of them disagreed on a missing organism — one counted Unknown as a genus, the other dropped the row — so the genus denominator of the same set depended on which script you ran. The genus is now read from the NCBI taxonomy rank: the nearest ancestor of the genome record's taxon whose rank is exactly genus. One reader owns the question; the validator fails if a second local implementation appears.

Did the correction change a verdict? It has to be asked, because changing the unit of a test can reverse it, and “I changed the definition and nothing moved” is not the same statement as “I changed it and the result flipped.” The genus-level promoter test was recomputed on the same data under both definitions: with the NCBI rank the effect size is {{ '%.3f'|format(sens.ncbi_rank.cliffs_delta) }} (p = {{ '%.1e'|format(sens.ncbi_rank.p) }}), with the first word of the organism name {{ '%.3f'|format(sens.first_word_of_organism.cliffs_delta) }} (p = {{ '%.1e'|format(sens.first_word_of_organism.p) }}). The verdict does not move. The genus definition was wrong and is now right; that it did not rescue or destroy a published claim is a measurement, not an assumption, and it is recomputed on every run rather than written here once. The two rows are in promoter_architecture.json under genus_unit_sensitivity.

Why the lineage already in the record was not enough

Each GenBank record also carries a semicolon-separated lineage, and the obvious repair is to call its last field the genus. That was measured and rejected: in 2,006 of 17,074 records (11.7%) the last field is not a genus but a species complex — Mycobacterium tuberculosis complex, Bacillus cereus group, Ralstonia solanacearum species complex. The lineage string carries no rank labels, so field position does not mean rank. Rank has to come from nodes.dmp, which is why the taxonomy dump is a pipeline input.

The database's seventh largest “genus” is not a genus

The organism strings name Mycolicibacterium on {{ '{:,}'.format(gtax.genus_unassigned.entries) }}-odd entries, which under the first-word rule made it this database's seventh largest genus, between Rhodococcus and Novosphingobium. In the current NCBI taxonomy it is a subgenus: Mycobacterium (subgen. Mycolicibacterium), and the lineage of Mycolicibacterium fortuitum runs species → subgenus → family Mycobacteriaceae, with no genus node on the way. So a published genus-level signal was resting on a genus that does not exist. Dropping those entries would have shrunk the denominator silently; folding them into Mycobacterium would have asserted a placement NCBI does not make. They are carried with their nearest named rank and counted separately.

NCBI is not internally consistent here, and that is reported rather than tidied: the same-shaped node for Mycolicibacter (taxid 1073531) carries rank genus, while the one for Mycolicibacterium carries rank subgenus. Rank is taken from the source as it stands.
